## 리플레이 측정 (`Fixtures/replay-novel-ko-v1.txt`, 12컷)

재현: `docs/m5-replay-bench.md` 절차 + `--knowledge` (③).

| 구성 | 수락 프록시 | 어절 적중 | 콜드 TTFC | 웜 TTFC |
|---|---|---|---|---|
| ① Fast (1200자) nano | 0.4자 / 0% | 8% | 0.39s | 0.01s |
| ② 4000자+헤더 nano | 0.4자 / 0% | 8% | 0.42s | 0.02s |
| ③ 1200자+헤더+지식 nano | 0.4자 / 0% | 8% | 0.28s | 0.01s |
| ① air(3B) | 0.4자 / 0% | 8% | 0.50s | 0.02s |
| ③ air(3B) | 0.3자 / 0% | 8% | 0.54s | 0.02s |

**판정 — 완료 기준(수락 프록시 상승) 여전히 미달.** 해석:

1. **지표가 과제와 어긋난다.** 문장 경계 컷의 정답은 "다음 문단 첫 마디" —
   서사 자유도가 커서 12토큰 접두 일치는 지식으로도 못 올리는 지표다.
   ①=②=③ 완전 동률이 그 증거 (지식이 있든 없든 0%대 천장).
   **다음 액션**: M7의 실사용 수락률 로깅이 진짜 지표. 벤치는 보조 지표
   (어절 적중)를 씬 중간 컷과 함께 확장할 것.
2. **nano 요약 품질은 미달, air는 사용 가능** (선결정-2 답):
   nano 씬 요약엔 사실 오류·환각(연도·"18:18")이 섞이고 작품 요약은 반복 붕괴.
   air(3B)는 대체로 정확했다. 잘못된 요약의 주입은 중립이 아니라 **해롭다**
   (③ nano에서 요약의 틀린 연도가 제안에 새어 나옴) — 요약 생성은 air 이상을
   권장, nano 전용 사용자는 B 블록이 약이 아니라 독일 수 있다 (§16 열린 질문).
3. **웜 경로는 B 블록이 공짜** — 스냅샷이 유휴에서만 바뀌어 KV 프리픽스가
   안정적. 설계 의도(PLAN §12) 그대로.

### 인물 감지 정밀도 — 빈도 기반 → 유정성 신호 기반 (2026-07-14 개선)

**초판 문제 (빈도·조사 휴리스틱):** 상위 후보가
`도경 · 인호 · 등대 · 일지 · 등불` — 실제 인물 2, 사물 오탐 3 (**Precision 40%**).
대명사·접속사·동사도 조사처럼 보이는 접미를 떼면 이름 어간으로 새어 들어왔다
("그러나"·"버리고"·"그").

**원인 분석:** 토크나이저에 품사 개념이 없었다. 그런데 한국어는 `NLTagger`가
품사·개체명을 지원하지 않는다(실측: 한국어 가용 스킴 Language·Script·TokenType뿐,
"한도경은" 조사 분리조차 못 함). 형태소 분석기에 기댈 수 없다.

**구조적 해법 (`CharacterLexicon` + `CharacterDetector` 재작성):** 교착어 구조로
품사 없이 품사를 판별한다.
1. **격조사는 체언에만 붙는다** → 동사·형용사·부사·접속사는 격 증거가 없어 후보
   자체가 안 된다. 비명사 오탐이 구조적으로 소멸.
2. **여격·호격·발화 귀속은 유정물(사람) 전용** → 이 신호를 **후보의 필수 조건**으로.
   사물(일지·등불)은 격조사는 취해도 이 신호를 못 받아 탈락.
3. 대명사·호칭은 닫힌 부류 목록으로 제외. 동음이의("소리")는 불용어로 뭉개지 않고
   발화 귀속 신호로만 통과 — 구조 신호가 불용어보다 낫다는 실증.

**결과:**

| | 초판(빈도) | 개선(유정성) |
|---|---|---|
| Precision (v1 픽스처) | 40% (2/5) | **100% (3/3)** |
| Recall | 100% | 100% |
| 적대적 케이스(그러나·그·버리고·소장님·아버지 빈발) | 다수 오탐 | **0 오탐** |

적대적 픽스처(`scratchpad/adversarial.txt`)에서 "소장님"·"아버지"는 발화 귀속으로
유정 신호를 받지만 **호칭 목록으로 정확히 제외**됐다 — 이것이 고유명사만 남기는 핵심.

**확장성:** 언어 구조(격조사·유정 신호)는 내부 인프라, 일반명사 불용어는
`~/Documents/MINT/character-stopwords.txt`에 한 줄씩 추가 → **재빌드 없이** 병합
(mtime 캐시, 검증 완료). 재현: `MINTBench --detect-only --replay <원고> --true-people "a,b"`.

**정밀도 우선의 대가 (의도된 것):** 유정 신호가 하나도 없는 인물(현재 창에서
발화·상호작용이 전무한 조연)은 침묵으로 놓친다. 원고가 자라 발화/여격이 생기면
다음 패스가 잡고, 등록은 어차피 사용자 확인이라 안전하다 (CLAUDE.md §2 품질>적극성).

## A+B 프리픽스 KV 프리웜 (2026-07-17, PLAN §12-1) — ⚠️ 같은 날 제거됨

**제거 (2026-07-17 오후)**: 머지 후 실사용에서 타이핑 랙 회귀 보고. 원인 분석 —
패스 완주 신호가 **빠른 패스(5s 유휴)에도** 발화해, "쓰다 잠깐 멈춤"마다 최대
3072토큰 프리필이 GPU를 점유하고, 시작된 프리필은 설계상 취소 불가라 타이핑
재개 시 다음 예측이 엔진 뒤에서 대기했다. m6-prep 7단계의 "프리웜 무효화 빈도를
먼저 측정하고 붙인다"를 어긴 것이 근본 원인. 재도입 조건은 PLAN §12.
아래 기록은 제거된 설계의 보존이다 — 재도입 시 참조.

⚠️ 사용자 보고에 "자동완성을 꺼도 랙"이 있었다 — 프리웜 단독 범인과는 안 맞는
관찰. 제거와 함께 `noteChange`에 자동완성 OFF 가드를 추가해(OFF = 이해 관련
키 입력 비용 문자 그대로 0) 대조군을 깨끗하게 만들었다. OFF에서도 랙이 남으면
원인은 에디터·저장 경로다 — 그때는 프로파일링으로 간다.

지식 세대가 바뀌면 다음 예측 프롬프트는 헤더 첫 글자부터 어긋나 LCP가 죽고,
A+B+C 전체가 콜드 프리필이 된다(최대 3072토큰). 그 프리필을 **이해 패스 직후의
유휴 시간**으로 옮겼다 — "백그라운드가 준비하고 예측은 조립만"의 KV 레벨 구현.

- 경로: `BackgroundIndexer.onPassDidComplete`(패스 **완주** 시에만 — 선점된
  패스는 타이핑 재개라 프리웜 자리가 아니다) → `CompletionController.prewarmPrefix`
  → `CompletionEngine.prewarm`.
- **프롬프트 동일성이 핵심**: 컨트롤러가 마지막 편집의 창(prefix·커서)을 기록해
  두고, 예측(`runCompletion`)과 완전히 같은 `assemble` 호출로 조립한다. 엔진도
  별도 프리필 API 대신 예측과 같은 `runGeneration`을 **maxTokens=1**로 태운다 —
  클램프·begin/commit 규율이 같아 프리웜된 캐시가 예측의 LCP와 어긋날 수 없다.
- 무조건 호출해도 싸다: 지식이 안 바뀐 패스면 LCP가 전부라 1토큰 프리필로 끝.
- 게이트: 자동완성 on · 엔진 ready(모델 로드 유발 금지) · continuation+KV on ·
  열 상태 · 예측 비진행. 타이핑 재개(`invalidate`)·문서 전환이 프리웜을 취소한다.
- ⚠️ **측정은 실기기 E2E 대기**: 예측 경로 코드는 불변이라 벤치 수치는 그대로다.
  검증 절차 — 소설 문서에서 문단 몇 개 편집 → 60s 유휴(깊은 패스+프리웜) →
  타이핑 재개 → 첫 제안의 상태 바 지연이 웜(≤0.1s급)인지. 프리웜 없이는 같은
  상황에서 콜드(수백 ms~s)였다.
