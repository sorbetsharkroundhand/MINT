Issue #269 extends completed source search, not the prediction/retrieval architecture. The owner delegates UI/internal choices and inline reviews without subagents/repeated approval. Model choice remains manual and actual app acceptance is owner-later. No local product launch, shipping LLM operation or model download is part of implementation verification.

## Interaction
Keep the existing transient original-source search panel and Here/Chapter/Project controls. After a normal word/name search, an optional “이 결과로 질문” action opens a question/result mode in the same panel. It states the scope and number of supplied originals. The writer enters a question and explicitly starts it; opening/searching never starts a model. Back returns to search. Source actions reuse ProjectEditorRequests jump/return; closing restores editor focus. The manuscript/native editor and Undo owner remain mounted.

Without an available already-loaded selected local model, search stays useful and the optional answer action explains model readiness. No default model choice, automatic download, permanent chat sidebar, automatic rewrite, inferred canon update or autonomous retrieval loop. Each new question captures fresh search evidence and starts a fresh instruction cache; cancelled/stale answer prompt state is not resumed.

## Original evidence and response contract
Prepare an immutable AskEvidencePacket from SourceSearchInput through the existing SourceSearch.results implementation, validating full project/runtime origin, live documents, captured revisions and exact raw UTF-16 quotes. Explicit inspection may include future manuscript passages within the requested scope; this packet is never routed into Ghost. Keep at most eight original hits, 1,024 UTF-16 units per quote and 8,192 in total; refuse oversized hits without truncating originals. Retain bounded hits/anchors, packet nonce, scope and origin, not a full manuscript body. Source IDs S1…S8 identify only this packet. A runtime token-budget check rejects an oversized templated prompt without silently truncating citations.

The local model receives bounded original evidence, a question (maximum 500 UTF-16 units) and a JSON-lines response contract. Each published answer block contains bounded Markdown text plus nonempty source IDs and exact original quotations. Validate complete records before displaying them: unknown/duplicate/malformed citations, nonliteral quotations, empty/oversized records and unsupported citation markers refuse the entire block. Raw unfinished/invalid model prose is never published. An explicit insufficient-evidence status makes no claim. Limit buffered input and accepted blocks; malformed trailing output can stop generation while retaining prior validated blocks.

Citation grounding is deterministic, not proof of semantic entailment. Answer text remains visibly AI interpretation beside its original evidence; it never becomes a hard continuity warning, WriterDecision or canon. No model-supplied URL or document identity becomes a navigation action. Render Markdown read-only with external model links/attachments inert; only packet-owned source actions navigate after current ownership/original verification.

Packet preparation takes the first eight real search hits and refuses invalid/oversized original quotes; oversized display titles use a bounded label without editing the document. Response limits are 8,192 buffered UTF-16 units, 65,536 total units, 20 accepted blocks, 2,000 units per text and one to four unique citations per block. A quotation must be one literal unique occurrence within its packet original (the full original is always eligible). Errors close the decoder and retain its accepted blocks for the owner-scoped controller; finish cannot resume an old request.

## Lifetime and priority
An injected cancellable answer backend and controller capture runtime identity, packet nonce and request ticket. Project/document/body changes, transition, model retirement, memory pressure and thermal/low-power gates retire work; late streams cannot publish into another request/project. User Cancel preserves already validated partial blocks while the original owner remains current. A new question clears old content only through that explicit action. Typing and foreground Ghost cancel answer work immediately through existing ownership/activity signals. Backend cancellation drains its existing generation synchronizer before model/container handoff. Never auto-resume a stale request.

The production backend uses only the already-loaded expected model and normal model-lifetime admission, fresh instruction state and bounded generation. If the model becomes unavailable, fail without choosing/loading/downloading another model. Preserve existing continuation/prompt-cache behavior and public completion callers. No new background scan, inference or work is added to prediction.

## Result accessibility and scrolling
The read-only result supports selectable Markdown, keyboard/VoiceOver source actions, Cancel/Back and marked-text-safe question submission. Append validated blocks without replacing selection. Follow output only while the user owns the bottom position; scrolling upward stops following, and returning to the bottom restores it. Cancellation/late status changes never seize scroll/focus. Actual native/IME/appearance acceptance remains #119; synthetic native tests cover layout/action ownership.
