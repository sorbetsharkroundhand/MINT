# Read-first Fiction Story Map

## Intent and authority
The owner requests all remaining UI/internal features, delegates recommended choices and written-artifact/inline author review without subagents or repeated approval, and handles actual app checks later. Current #113 and #99 retain a read-first map, existing NarrativeGraph/NarrativeProjection reuse, source jumps, plot/character/chronology filtering, current scene and project isolation. This is an architectural sub-project with three bounded delivery slices. No model setup, generation, manuscript reorder or durable writer mutation is introduced.

## Approach
Reuse the pure existing GraphRow and ThreadGraphLayout algorithms in a background value projector; render a new read-only project-owned surface. Wrapping legacy NarrativeView would retain EntryStore mutations and view-time graph calculation. Reimplementing graph topology would duplicate tested algorithms. Neither fits the current project owner as well as a small prepared projection.

## Projection boundary
StoryMapProjection is a Sendable value containing source-ordered scene/event rows, verified original anchors, source ranges, per-event lane slots and plot membership, selectable character/thread options and a full original revision. Scene row identity is the captured source offset, never a persistent manuscript identity or scene hash. Without a current verified knowledge snapshot, prepare source scenes from DocumentOutline only; no model is needed. Missing original event quotes remain quiet. Whole-source SHA, project/document scope and runtime ownership gate existing derived data. Duplicate scene hashes cannot enter the legacy unique-key projection; use source scene rows instead. Cap graph reuse at8192 scenes/events and128 threads and refuse graph data beyond caps; source-only scenes stay available. Current source remains authoritative.

Flow and story chronology reuse existing GraphRow ordering and ThreadGraphLayout. Unknown time retains existing stable source ordering, without inventing a complete chronology. Filters intersect plot and character membership, preserve order within the selected projection and retain context scene markers. Filtering never changes manuscripts or membership. Scene source lookup uses sorted offsets/binary search, independent of filtered visibility. Repeated original passages keep exact offsets.

## Runtime and source actions
A main-actor StoryMapController owns a cancellable utility worker, epoch and current ProjectRuntimeIdentity. It receives captured document and matching indexer snapshot/generation; opening/painting a view never computes a graph or scans disk. Edits/project/mode/transition changes clear source actions synchronously; noncooperative stale work cannot publish. Preparation is debounced and paused under foreground Ghost, memory pressure, serious/critical thermal state and low power. Original-byte/project memoization stays in a bounded background cache. No automatic model work occurs.

A native source target carries current runtime, revision and exact anchor/offset through the established source-navigation bridge. It preserves selection/scroll return, focus, IME and undo; stale or unowned targets refuse without mutation. The project shell exposes Fiction Write/Map and keeps General Write/Outline. Map uses the existing docked context allocation and opaque paper while the editor stays mounted. Closing returns to Write. Filters/selection reset on owner change. Read-only scene/event rows, lane marks, explicit labels and a return action work with keyboard accessibility; subjective native acceptance remains #119.

## Validation and completion
Regression-first projection tests cover deterministic reuse, filters/source ordering, chronology/unknown time, originals/raw Unicode, duplicate scenes, wrong scope/revision, empty/model-free scenes, bounds and cancellation. Runtime tests cover detached work, stale A→B→A/edit/mode ownership, priority/policy/cache and current-scene lookup. Synthetic native tests prove jump/return/marked-text/stale refusal and retained editor/undo. Preserve NarrativeGraph and performance suites plus PurloryBench compile. Each slice needs focused/full tests/build/bench and inline review, exact-head/predecessor-main/final-main all-three CI. No local Purlory launch or actual model/native acceptance is fabricated.

Author review: interfaces have producers and consumers; source hash is not durable identity; read-first flow has no legacy write owner; actual graph work stays outside rendering; owner-native/model gates stay separate. No unresolved design issue.
