## Approach
Keep deterministic comparison outside model and editor code. A private-construction `ContinuityCandidate` carries scope, captured source revision, kind, subject, explanation, original EvidenceAnchor values and relevant derived fact IDs. It is a candidate for bounded judging/review, never canon or an automatic hard warning. Use current verified `StoryKnowledgeSnapshot.observations(before:)`; no project scan, full body retention, inferred time or model load. Alternatives of free-form keyword contradictions or treating absence as not-knowing are rejected.

## Rules
- Admit only original-verified observations in the exact scope and completed discourse context; high-confidence means finite >=0.8 or snapshot-verified writer confirmation. Preserve raw originals, reject nil confidence, low confidence and unknown scope/time. Same explicit timeline and overlapping known intervals are required for knowledge/location/relationship conflicts.
- Add `CharacterKnowledge.Stance.unaware` for an explicit lack of knowledge. `.unknown`, suspects, hides and misbelieves do not imply ignorance. Only the same character/fact with unaware versus knows at overlapping known time creates a knowledge-leak candidate. Never use missing knowledge as evidence.
- Different location values for the same character at known overlap create a location candidate. Place containment/aliases are not resolved into a hard claim; the bounded judge may return intentionalPossible/noConflict/insufficientEvidence.
- Explicit opposing relationship labels on the same directed pair at known overlap create a relationship/identity candidate. Initial closed pairs: `배우자`/`배우자 아님`, `친부`/`친부 아님`, `친모`/`친모 아님`, `동일인`/`다른 인물`. Arbitrary differing roles are compatible and silent.
- Object condition transitions from `파괴됨` or `소실` to `온전함` or `존재` create a reappearance candidate only on the same known timeline in nondecreasing story order. Any intervening condition observation, even uncertain/low confidence, breaks the pair; explicit restoration therefore does not produce a false missing-transition claim. Retelling/flashback is ordered by explicit story time, not discourse. Model/semantic uncertainty is adjudicated in #110.
- Add typed `CharacterAge` with characterID, completedYears (nonnegative Int64), calendarYear (Int64), calendarID (nonempty bounded string), and StoryFact.Content.characterAge. Do not interpret StoryInstant.tick as years. Compare two explicit completed-year observations only in the same calendar: possible birth-year intervals `[year-age-1, year-age]` must overlap. Checked arithmetic refuses overflow. Unknown age conventions/timing are not typed into this assertion.
- Deduplicate identical logical contradictions across repeated original observations. Candidate identity is scoped and deterministic; ordering follows original discourse. All candidates carry both originals and fact IDs; malformed/cancelled work yields no partial publication. Bound retained output to128 candidates. No user-facing conflict until evidence/visibility/judging contracts pass.
- BackgroundIndexer prepares these candidates alongside original-backed legacy warnings, under the existing body/runtime/generation checks. Edits, project transitions and pressure retirement clear candidate actions synchronously. Legacy dead/honorific warnings can be adapted only from their original-backed overload. Prepared candidates do not start inference or open tools.
