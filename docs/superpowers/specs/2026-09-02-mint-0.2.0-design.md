# MINT 0.2.0 Design Specification

**Epic:** #99  
**Theme:** Writing Platform, Fiction First  
**Status:** approved design baseline  
**Target:** macOS 14+, Apple Silicon, Swift 6, SwiftUI + AppKit, MLX, local-only

## 1. Product Definition

MINT 0.2.0 is a **local AI writing platform**. Fiction is the first deep specialization, not the top-level product identity.

The platform must remain useful for General Writing while Fiction receives the richest intelligence layer in 0.2.0.

Core statement:

> MINT is a local writing environment that understands the context of what you write without taking control away from the writer.

## 2. Product Invariants

1. Writing Platform, Fiction First.
2. Editor quality is primary; AI is optional.
3. No remote inference or telemetry.
4. User manuscript and user decisions are durable user-owned data.
5. AI-derived knowledge is rebuildable cache.
6. User Canon overrides automatic inference.
7. Evidence-first: important warnings must point to original manuscript evidence.
8. Quiet AI: silence is preferred over low-confidence interruption.
9. Prediction owns foreground priority; background intelligence yields immediately.
10. Existing Hangul IME behavior, Ghost Completion keyboard semantics, and **cursor line highlight** are preserved.
11. Glass is not removed wholesale. The editor gets a stable opaque surface; material/glass is reserved for toolbar, navigator, popovers, Ask MINT, and contextual intelligence surfaces.
12. `DocumentOutline.Scene` remains a derived analysis object and must not become the persistent manuscript scene identity.
13. Existing `SourceAnchor` remains the re-anchoring utility namespace. Persistent/cross-layer evidence values use a new `EvidenceAnchor` type that delegates resilient text lookup to `SourceAnchor`.

## 3. Architecture

```text
MINT
├─ Writing Platform
│  ├─ WritingProject
│  ├─ WritingDocument
│  ├─ ProjectStore
│  ├─ Project Navigator
│  ├─ Editor
│  ├─ Search / Export
│  ├─ Ask MINT
│  └─ Local AI Runtime
│
├─ Writing Intelligence
│  ├─ Ghost Completion
│  ├─ Context Retrieval
│  ├─ Living Margin
│  └─ Review Contract
│
└─ Fiction Intelligence
   ├─ Scene / Event / Character
   ├─ Character Knowledge
   ├─ Relationship / Object State
   ├─ Timeline
   ├─ Story Threads
   ├─ Hierarchical Story Memory
   ├─ Evidence Retrieval
   ├─ Continuity Detection
   └─ Story Map
```

General Writing must compile and function without depending on Fiction-specific scene, character, timeline, or continuity types.

## 4. Project Domain

The top-level persistent domain becomes `WritingProject` rather than a novel/manuscript type.

```swift
public enum WritingMode: String, Codable, Sendable {
    case general
    case fiction
}

public struct WritingProjectID: Hashable, Codable, Sendable {
    public let rawValue: UUID
}

public struct WritingDocumentID: Hashable, Codable, Sendable {
    public let rawValue: UUID
}

public struct WritingProject: Codable, Sendable {
    public var id: WritingProjectID
    public var title: String
    public var mode: WritingMode
    public var documents: [WritingDocument]
}
```

Persistent Fiction scene identity, if required, is a Fiction-domain type and must not reuse `DocumentOutline.Scene` hashes as durable identity.

## 5. Storage and Migration

Target storage:

```text
~/Documents/MINT/Projects/<project-id>/
├─ project.json
├─ Documents/
├─ Notes/
├─ Assets/
└─ Intelligence/
```

Migration is non-destructive:

```text
entries.json
  → read legacy snapshot
  → create a new WritingProject separately
  → serialize all documents/assets/metadata
  → verify manuscript equality
  → activate the new project

entries.json remains unchanged
```

No in-place migration of the legacy source file is allowed for 0.2.0.

User Canon belongs to project-owned durable metadata, never to rebuildable KnowledgeSidecar data.

## 6. Workspace UX

### Shared shell

```text
Toolbar: Project / workspace mode / Ask MINT
──────────────────────────────────────────
Project Navigator | Editor | Living Margin
──────────────────────────────────────────
Status / local readiness
```

### Fiction

```text
Write | Map | Review
```

### General Writing

```text
Write | Outline | Review
```

The navigator is content-centric. Users navigate their projects, documents, chapters, notes, and research instead of navigating implementation features such as Files/Bible/Narrative/Context/Agent.

## 7. Visual Direction

0.2.0 uses a dark editorial workspace with selective material.

- Window background: dark neutral semantic surface.
- Editor: stable opaque surface, visually close to the window background.
- Navigator/toolbar/floating panels: restrained material.
- Living Margin: low-noise contextual surface.
- Ask MINT: temporary material panel.
- Borders/cards: minimized; hierarchy comes from typography, spacing, alignment, and contrast.
- One MINT accent plus semantic warning/danger tokens.
- No stacked transparency.
- Cursor line highlight remains part of the focused writing experience.

## 8. Evidence Contract

The current `SourceAnchor` enum remains a utility namespace for resilient source lookup. A new value type carries evidence between Project, Knowledge, Living Margin, Review, and Ask MINT:

```swift
public struct EvidenceAnchor: Codable, Equatable, Hashable, Sendable {
    public var documentID: WritingDocumentID
    public var sceneHash: String?
    public var quote: String
    public var utf16Hint: Int?

    public func resolvedQuery(in body: String) -> String?
}
```

`resolvedQuery(in:)` delegates resilient matching to `SourceAnchor.resilientQuery(for:in:)`. `utf16Hint` is only a hint; after edits, a jump is valid only when the evidence can be re-anchored.

## 9. Living Margin

Living Margin is a presentation primitive shared across modes.

```swift
public struct MarginInsight: Identifiable, Sendable {
    public enum Kind: Sendable {
        case continuity
        case openThread
        case sceneContext
        case suggestion
        case generalReview
    }

    public var id: String
    public var kind: Kind
    public var title: String
    public var message: String
    public var evidence: [EvidenceAnchor]
    public var confidence: Double?
    public var actions: [MarginAction]
}
```

Rules:

- Do not annotate the manuscript aggressively with AI underlines or popups.
- Warnings use confirmation language, not absolute declarations.
- Evidence jump is available for consequential warnings.
- Empty/low-confidence state should be visually quiet.

## 10. Fiction Story Memory

The existing summary pyramid becomes an explicit retrieval structure:

```text
Work
└─ Part / Arc
   └─ Chapter
      └─ Scene
         └─ Atomic Story Knowledge
```

Atomic knowledge includes:

- Event
- Fact
- CharacterState
- CharacterKnowledge
- RelationshipState
- ObjectState
- StoryThread

The pyramid is a **router**, not the truth source. A mismatch between summaries may generate a candidate, but user-facing warnings require drill-down to original text evidence.

Dirty propagation must remain incremental:

1. changed scene invalidates scene memory;
2. changed child hash invalidates its chapter;
3. changed chapter invalidates work summary;
4. unchanged siblings are not recomputed.

## 11. Temporal Model

Fiction requires two time axes:

- discourse position: order in the manuscript;
- story time: order/time in the fictional world.

Unknown story time remains unknown. The system must not generate strong temporal conflict warnings from unknown time.

Character knowledge is time-aware. A character may not use facts before the point where the knowledge was acquired unless User Canon or explicit manuscript evidence says otherwise.

## 12. Retrieval

Retrieval is structure-first:

```text
Current scene
→ adjacent scenes
→ entity reverse indexes
→ event/state/relationship indexes
→ timeline / narrative graph
→ chapter/work summaries as routing hints
→ local full-text search
→ optional semantic fallback
```

Every retrieval candidate records why it was selected and resolves to an `EvidenceAnchor` when it may become user-visible evidence.

Semantic embeddings are optional fallback, not a mandatory always-resident dependency for 0.2.0.

## 13. Continuity Pipeline

```text
Text change
→ background extraction
→ deterministic candidate checks
→ structure-first retrieval
→ original evidence packet
→ Agent Judge when ambiguity remains
→ confidence/evidence gate
→ Living Margin / Review
```

Deterministic checks include the existing dead-speaker and honorific-break behavior plus explicit knowledge, location, time, object-state, relationship, and identity conflicts when evidence is strong enough.

Agent Judge receives a bounded evidence packet rather than unrestricted whole-project search.

```swift
public struct ContinuityJudgementRequest: Sendable {
    public var current: SourceExcerpt
    public var evidence: [SourceExcerpt]
    public var candidate: ContinuityCandidate
}
```

Each `SourceExcerpt` carries an `EvidenceAnchor`. A high-severity conflict without cited, resolvable original anchors must not be shown.

## 14. User Canon

Priority:

```text
User Canon
> explicit manuscript text
> deterministic inference
> Agent inference
> summary
```

`Intentional` and `Dismiss` are separate actions.

- Dismiss suppresses presentation state.
- Intentional creates a durable user-owned decision.
- Correction updates the canonical value/interval.

Reindexing or KnowledgeSidecar schema bumps must never delete User Canon.

## 15. Ask MINT

The `mint-agentic` branch is mined, not merged wholesale.

Reusable engine/tool/context code moves under `Sources/MINTCore/Agent/`; the old permanent Agent surface is replaced by `⌘K` Ask MINT.

Scopes:

- Here
- Chapter/Document
- Project

Ask MINT is evidence-first, project-isolated, cancellable, and local-only. Existing #19 streaming behavior and #28 Markdown/accessibility requirements are absorbed by #112.

## 16. Story Map and Review

Story Map reuses current `NarrativeGraph` and `NarrativeProjection` as a read-first projection. 0.2.0 does not require a full editable graph authoring system.

Review is an inspection surface, not chat. It groups evidence-backed issues such as continuity, open threads, character knowledge, timeline, dialogue, and structure.

## 17. Ghost Completion

Ghost Completion stays a flagship feature.

The prediction hot path may read a prepared in-memory Story Memory snapshot but must not perform disk I/O or start a new retrieval/LLM job.

```text
Recent text
+ current scene context
+ relevant prepared memory
+ user canon
→ Ghost Completion
```

Foreground prediction preempts background indexing/judging.

## 18. General Writing

0.2.0 must prove the platform is not Fiction-only.

General Writing supports:

- project/document editing;
- navigator;
- Ghost Completion;
- Ask MINT;
- Review contract;
- Living Margin contract;
- export.

Fiction-specific Character/Timeline/Map controls must not appear.

## 19. Legacy UI Retirement

Replacement surfaces must land before removal.

- Context Inspector tab → Living Margin / Ask MINT.
- Narrative tab → Map / Review.
- Agent sidebar → Ask MINT.
- Story Bible UI → Fiction notes/intelligence surfaces while preserving underlying data.
- technical model names → Settings > Advanced.
- advanced formatting is retained where it belongs, but Fiction manuscript UI is simplified.

## 20. First Run

First-run priority:

```text
MINT
새 글 시작
기존 원고 가져오기
```

Mode selection follows project creation/import. The user must be able to start writing before configuring a model.

## 21. Release Definition

0.2.0 is complete only when:

- current CI baseline is green;
- migration proves legacy manuscript preservation;
- editor/IME/cursor-line/Ghost regressions are absent;
- General Writing is not coupled to Fiction;
- Story Intelligence provides hierarchical memory and evidence drill-down;
- continuity warnings cite source evidence;
- User Canon survives rebuilds;
- 100k–300k character fixtures remain responsive;
- foreground prediction successfully preempts background intelligence;
- app bundle smoke/UI smoke/release readiness are green.
