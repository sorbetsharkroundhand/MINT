# MINT 0.2.0 Platform Foundation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Introduce a general writing-project domain, safe project storage/migration, and mode-aware workspace routing without coupling the platform to Fiction.

**Architecture:** Add a focused `Project/` module beside the existing `Storage/` code. Keep `EntryStore` as the legacy compatibility boundary while new code reads/writes `WritingProject` values through `ProjectStore`. Workspace routing consumes only `WritingMode`; Fiction-specific data remains below `Sources/MINTCore/Fiction/` or `Knowledge/` and is not imported by the project domain.

**Tech Stack:** Swift 6, Foundation, SwiftUI, XCTest, Swift Package Manager

**Spec:** `docs/superpowers/specs/2026-09-02-mint-0.2.0-design.md`

## Global Constraints

- `WritingProject` is generic; Fiction is a mode, not the root type.
- General Writing must not depend on Fiction-only scene/character/timeline types.
- `DocumentOutline.Scene` is not a persistent project/document/scene identity.
- Existing `entries.json` is read-only input to migration and remains unchanged.
- Writes use atomic replace semantics and activate a migrated project only after validation.
- User-owned project metadata and User Canon are durable; derived Intelligence may be deleted and rebuilt.
- Preserve existing editor body content exactly during adaptation/migration.
- Every task ends with `swift test` and relevant focused tests; product code is not merged while #100 baseline is red.
