# MINT 0.2.0 Release Readiness Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Define and automate the evidence required to call MINT 0.2.0 a product-ready release candidate rather than a collection of merged features.

**Architecture:** Extend the existing Swift test suite, MINTBench, app-bundle scripts, UI smoke, and GitHub Actions release-readiness flow with project migration fixtures, long-document Fiction/General fixtures, cross-project intelligence isolation tests, foreground/background scheduling checks, and end-to-end evidence/Canon workflows.

**Tech Stack:** Swift 6, XCTest, MINTBench, shell scripts, GitHub Actions, macOS 15 CI runners targeting macOS 14+, MLX local inference

**Spec:** `docs/superpowers/specs/2026-09-02-mint-0.2.0-design.md`

## Global Constraints

- #100 must establish a green baseline before 0.2.0 gate changes are judged.
- Existing #65 stabilization requirements remain valid; #119 does not silently waive them.
- #18 visible-range/editor performance is a release dependency where long-document interaction still depends on it.
- UI smoke must preserve the existing `CFFIXED_USER_HOME` isolation contract.
- No release check may modify the user's real Documents/MINT data.
- Migration tests prove the original legacy bytes remain unchanged.
- Cursor-line highlight regression is release-blocking.
- Hangul IME and Ghost Tab/→/Esc regressions are release-blocking.
- Cross-project or future-knowledge leaks are release-blocking.
- High-severity continuity output without original evidence is release-blocking.
