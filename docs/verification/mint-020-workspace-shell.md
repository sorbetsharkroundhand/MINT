# #103 앱 셸 검증 기록

2026-09-06, macOS 로컬. 부모 #99. 브랜치 `codex/mint-020-workspace-shell`.

## 구현 범위

문서 트리를 기본 탐색기로 고정하고 기존 바이블·서사·컨텍스트는 보조 도구로
분리했다. 본문은 불투명 표면이며, 도구는 너비가 충분하면 오른쪽, 부족하면
편집기 아래에 공간을 확보한다. 기존 편집기의 줄 강조·IME·고스트 코드는
접근성 식별자 추가 외에는 변경하지 않았다.

플랫폼 기반 계획의 Task 5(#104)가 ProjectSession을 소유하므로 이번 단계는
EntryStore 어댑터를 유지한다. WritingProject 문서 투영·프로젝트 간 선택 격리는
ProjectSession 연결과 함께 추가 검증해야 한다. 실제 프로젝트 전환 완료로
해석하지 않는다.

  저장/복구/undo 회귀 포함. 새 검사는 탐색기 폭과 테마 불투명성 2개만 추가.
- `swift build`: 통과.

- `sh -n scripts/ui-smoke-mint-app.sh`, `git diff --check`: 통과.
- 독립 소스 리뷰: 좁은 창 도구 오버레이가 커서를 가리는 문제를 수정했고,
  재검토에서 추가 중요 결함이 없었다.

## 격리 UI 검사

고유 번들 ID의 복사 앱과 `CFFIXED_USER_HOME`을 사용했다. 모델은 비활성화했고
합성 소설·저널의 고유 본문을 화면에서 확인한 뒤에만 입력했다.

자동 스크립트는 `osascript` 손쉬운 사용 접근 거부(-25211)로 중단됐다.
권한을 변경하지 않고 기존 UI 제어 도구로 같은 격리 앱을 검사했다.

확인한 항목:

- 문서 중심 탐색기 기본 진입 및 소설/저널 본문 전환.
- 탐색기 접기/펼치기와 폭 250→340 변경, 재실행 후 폭 340 보존.
- 바이블을 열어도 탐색기 유지. 넓은 창 오른쪽/좁은 공간 하단 배치.
- 도구 열기·닫기, 탐색기 접기, 문서 전환 뒤 편집기 포커스 유지.
- 새 문서 단축키 입력, 정상 종료·재실행 후 `relaunch-check` 본문 보존.
- 라이트/다크의 불투명 본문과 현재 커서 줄 강조 시각 확인.
- 실제 한글 입력 소스를 통한 `ㅎ→하→한` 조합·확정. 입력 소스 복원.
- 키보드 검색 진입, Tab으로 문서 행 이동 후 Enter로 선택.

## 아직 완료로 판정하지 않은 항목

- 실제 모델 고스트 생성 및 Tab/→/Esc 수락·거절 E2E. 모델 비활성화 스모크는
  이 검증을 대신하지 않는다. 예측 품질·지연에 대한 새 주장은 하지 않는다.
- 시스템 투명도 감소 설정에서의 실제 화면 확인. 소스의 불투명 대체 경로와
  테마 값 검사는 있으나 시스템 설정을 변경해 검증하지 않았다.
- WritingProject 기반 프로젝트 A→B 전환 및 선택 격리(세션 연결 단계).

위 항목이 남아 있으므로 #103을 자동 종료하거나 Epic 완료 체크하지 않는다.
