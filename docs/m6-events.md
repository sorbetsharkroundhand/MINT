# M6-5 사건 로그 + 인물 역색인 + StateDelta — 설계

PLAN §6.2–6.3·§8 구현 설계. 착수 순서는 [m6-prep.md](m6-prep.md) 5단계,
앞 단계 구현 기록은 [m6-knowledge.md](m6-knowledge.md).

## 왜 지금인가

B 블록은 지금 요약 피라미드만 쓴다. PLAN §14가 `state_at`의 시점 차단을
"사건 로그와 함께"로 묶어둔 이유는, 요약은 **씬 단위 해상도**라 "민준이 언제
죽었나"·"서연이 지금 어디 있나"를 질의할 수 없기 때문이다. 사건 로그가 없으면
인물 카드의 `상태@커서` 줄(PLAN §7 카드 스키마)이 만들어지지 않는다.

## 결정 1 — 앵커는 Pos가 아니라 씬 콘텐츠 해시

PLAN §6.3의 스키마는 `Event { pos, ... }`지만 **`pos: Int`를 저장하지 않는다.**

- 근거: 씬 배열 인덱스(Pos v1)는 씬 하나가 삽입되면 뒤가 전부 밀린다. 저장하면
  삽입마다 전 사건의 pos를 재기록해야 한다 — append-only(§6.3)와 정면 충돌.
- 기존 자산과의 정합: `sceneSummaries`가 이미 `contentHash` 키다. 해시는 원문에
  매여 있어 삽입에 불변이고, Pos는 아웃라인 순서에서 파생하면 된다
  (`DocumentOutline.scenes` 배열 인덱스 = Pos, 이미 존재).
- **톰스톤이 공짜로 나온다**: 블록이 수정되면 해시가 바뀌어 사건이 고아가 되고,
  `save(pruningTo: liveHashes)`의 기존 GC 경로가 그대로 청소한다. PLAN §8
  "편집 무효화 규칙"을 새 코드 없이 만족한다.

Pos는 **질의 시점에** 파생한다: `sceneHash → outline 인덱스` 맵을 스냅샷이
만든다. 아웃라인에 없는 해시 = 톰스톤 = 질의에서 제외.

## 결정 2 — 참여 엔티티는 등록된 카드만 참조

`participants: [UUID]`는 `CharacterCard.id`만 담는다. 미등록 이름이 사건에
등장해도 링크하지 않는다 — **자동 등록 금지**(CLAUDE.md §3)의 연장이다.
미등록 인물은 감지 깔때기(§7)가 사용자 확인을 받은 뒤에야 사건에 연결된다.

부작용: 등록 전 사건은 참여자 없이 저장된다. 등록 시점에 그 인물의 과거 사건을
소급 연결해야 하는데, 사건 요약문에 이름이 남아 있으므로 **재추출 없이 이름
매칭으로 링크**한다 (등록은 드문 이벤트 — 전체 재추출은 과하다).

## 결정 3 — 추출은 요약과 별도 호출, 깊은 패스 전용

한 번의 호출로 요약+사건을 같이 뽑는 안을 기각한다:

- 요약 경로는 이미 측정·출시됐다(M6). 사건 추출의 파싱 실패가 요약까지
  같이 죽이면 회귀다 — 실패 격리가 낫다.
- 빠른 패스의 LLM 예산(≤2회, PLAN §9)은 **요약이 먼저 쓴다**. 사건은 유휴
  60s·앱 비활성의 깊은 패스에서만 (m6-prep 5단계 "깊은 패스 작업 추가").

비용: 씬당 LLM 1회 추가. 해시 메모라 같은 씬은 두 번 뽑지 않는다.

## 결정 4 — 출력은 JSON이 아니라 줄 형식

소형 모델의 JSON은 깨진다(중괄호 누락·트레일링 콤마). 요약 경로가 이미 평문 +
결정적 clamp를 쓰는 것과 같은 규율로 간다:

```
사건 | 참여: 서연, 민준 | 중요도: 3
```

파서는 관대하게, **검증은 엄격하게**: 참여자는 등록 카드 이름·별칭과 매칭되는
것만 남기고(환각 인물 차단), 중요도는 1–5 clamp, 요약은 80자 clamp.
한 줄도 파싱 안 되면 그 씬은 사건 없음으로 두고 다음 패스가 재시도한다.

## 결정 5 — 스키마 버전 2로 올린다 (기존 요약 폐기)

새 필드를 옵셔널로 얹어 기존 요약을 살리는 안을 기각한다 — CLAUDE.md §2-1이
"버전 올리고 재구축, 마이그레이션 코드 금지"를 명시한다. 옵셔널 수용은 구판
모양을 아는 코드의 시작이다.

**비용을 명시**: 기존 사이드카의 씬·장·작품 요약이 전부 날아가고 백그라운드가
다시 만든다. 유휴 시간의 일회성 비용이고 이후 해시 메모가 먹는다.

## 결정 6 — 사건은 B 블록에 나열하지 않고, 인물 카드의 "최근" 줄로 쓴다

구현 중 확정. 사건을 B 블록에 "앞선 사건: …" 줄로 넣으면 **같은 씬을 씬 요약이
이미 말하고 있어** 지식이 겹치고 예산(600자)만 태운다.

사건이 요약 대비 실제로 더 가진 것은 **참여자 링크**뿐이다. 그 값은 "인물 →
그 인물의 사건"이라는 질의에서만 나오므로, 산출을 카드 줄에 붙인다:

```
등장인물 서연(연이·서 대리): 신중, 직설적 · 최근: 서연이 퇴원하고 민준을 만났다
```

`lastAppearance(of:before:)`가 창 밖 사건만 돌려주므로, C 창이 이미 보고 있는
사건을 겹쳐 넣는 낭비가 질의 단계에서 이미 배제된다. 이 줄이 M6 완료 기준의
"1200자 창 밖 인물을 쓰는 제안"을 정면으로 겨눈다.

## 구현 중 잡은 것

- **모델 머리말이 사건으로 저장되던 문제**: "다음은 사건입니다:" 같은 줄이
  파서를 통과해 B 블록에 지식인 척 주입될 수 있었다. 구분자(`|`) 없는 줄을
  버리는 것으로 구조적으로 차단 — 형식을 지킨 줄에는 항상 `|`가 있다.
  형식을 벗어난 진짜 사건을 놓치는 비용은 받는다 (CLAUDE.md §1-2).
- **소급 연결의 필요**: 추출은 그 시점 등록 카드만 링크하므로, 나중에 등록된
  인물은 과거 사건에 영영 연결되지 않아 역색인에 구멍이 남는다 (그 인물의
  "최근" 줄이 영영 안 나온다). 등록마다 전 씬 재추출(LLM 비용 × 등록 횟수) 대신
  요약문 이름 매칭으로 잇는 `relinkParticipants`를 깊은 패스에 뒀다 —
  결정적·LLM 없음.

## 검증 (5a)

테스트 타깃이 없어(§16 부채) 파서·질의를 스크래치에서 컴파일해 확인했다.
결정적 로직이라 모델 없이 전부 재현된다:

- 파서 21건: 정상 형식·목록 기호·환각 인물 차단·조사 붙은 이름·머리말 차단·
  상한(씬당 3개·요약 80자)·중요도 clamp.
- 스냅샷 질의 16건: 담화 순서 정렬·역색인·**시점 차단**(커서가 2장 끝일 때
  3장의 "민준이 죽었다" 미누출)·`lastAppearance`·톰스톤 제외·중요도 정렬·
  **씬 삽입 후에도 사건 생존과 시점 차단 유지**(결정 1의 근거).

⚠️ 아직 **모델을 태운 E2E는 없다** — 추출 프롬프트가 실제 소형 모델에서 형식을
지키는지는 미측정. air 교체(2026-07-15)와 함께 재볼 것.

## 실측에서 드러난 것 (2026-07-15, 실제 원고 「날개」)

사이드카를 열어 본 결과 — 스크래치 검사가 잡지 못한 것들:

1. **선두 숫자 삭제 버그(수정됨)**: "33번지 18가구…"가 "번지 18가구…"로 저장됐다.
   목록 기호 제거가 `drop(while: "-*•0123456789. ")`라 숫자로 시작하는 본문을
   먹었다. `stripListMarker`로 교체 — `- `·`1. `·`2) `만 벗기고 "1930년"·"3.5초"는
   보존. 회귀 검사 5건 추가.
2. **참여자 빈 배열은 정상**: 등록 인물이 `아내` 하나인데 추출 구간(도입부)에
   등장하지 않는다. 버그 아님.
3. **⚠️ 헤딩 없는 장편이 씬 하나가 된다** — 「날개」 22,521자가 `# 날개` 헤딩
   하나뿐이라 **전체가 씬 1개**. `maxSceneCharacters = 1500`에 걸려 **앞 1,500자만
   (6.7%)** 요약·추출되고 21,000자는 지식에 존재하지 않는다. 사건 3개가 전부
   도입부 묘사인 이유이고, 장·작품 요약이 빈 이유(씬 2개 미만이라 전파 조건 미달)다.
   PLAN §8의 "골격 = 사용자의 헤딩 구조" 전제가 헤딩을 안 쓰는 원고(웹소설·단편)에서
   무너진다. **사건 로그 품질 이전의 문제** — §16 열린 질문으로 올린다.

## 단계 분할 (5a → 5b)

측정 가능한 단위로 쪼갠다:

- **5a — 사건 로그 + 역색인**: 추출·저장·`events(between:)`·
  `lastAppearance(of:before:)`. 산출: B 블록에 커서 이전 사건 줄, 카드에 "최근 등장".
- **5b — StateDelta + `state_at`**: 사건의 상태 효과를 델타로 뽑아 fold.
  산출: 카드의 `상태@커서` 줄. 필드는 **닫힌 집합**(위치·감정·관계·목표·생사)으로
  제한해 소형 모델의 자유 서술을 막는다.

5a가 먼저인 이유: 델타는 사건의 파생물(§6.3 `상태 효과 [StateDelta 참조]`)이라
사건 추출이 안정되기 전에 델타를 얹으면 두 실패가 섞여 원인 분리가 안 된다.

## 백그라운드 3요건 (CLAUDE.md §4) 대응

- **취소**: 씬 단위 체크포인트 — 기존 요약 루프와 같은 자리에서 `Task.isCancelled`.
- **게이트**: 깊은 패스 전용이라 `gateAllows(deep: true)`가 열·저전력 모두 커버.
- **메모**: `events[sceneHash]` 키 존재 = 추출 완료. 빈 배열 = "뽑았지만 사건
  없음" — nil과 구분해야 사건 없는 씬을 매 패스 재추출하지 않는다.
