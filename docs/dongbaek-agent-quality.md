# 「동백꽃」 Agent · Story Intelligence 품질 점검

측정일: 2026-07-22  
대상: 사용자의 로컬 `~/Documents/MINT/entries.json` 안 제목 `동백꽃`  
모델: `mlx-community/Qwen3.6-35B-A3B-4bit`, temperature 0.3

원문은 읽기만 했고, 사용자 인물 카드·핵심 장면·본문은 수정하지 않았다. 스키마
v8 재구축 결과만 버려도 다시 만들 수 있는 `MINT/knowledge/` 사이드카에 저장했다.
원문 전체는 이 보고서나 테스트 픽스처에 복제하지 않았다.

## 1. 판정 기준

Agent 골드 질문은 일곱 축 29개 개념으로 구성했다.

| 축 | 원문 대조 정답 |
|---|---|
| 서술 | 이름이 밝혀지지 않은 1인칭 화자이며 점순과 다른 인물 |
| 감자 | 점순의 호감·구애가 문맥상 동기. 화자가 거절하자 얼굴이 붉어지고 눈물, 도주 |
| 죽은 수탉 | 화자가 피투성이인 자기 수탉을 본 뒤 점순네 큰 수탉을 단매로 죽임 |
| 시간 | 서두 현재 → `나흘 전` 장기 회상 → `그랬던 걸 이렇게` 현재 복귀 |
| 관계 | 마름 집안과 의존 농가의 위계 + 호감·오해·닭싸움 갈등 + 동백꽃 결말 |
| 말투 | 결정적으로 점순에게 귀속된 원문 대사 두 개 |
| 플롯 | 감자 → 씨암탉 보복 → 고추장과 반복 닭싸움 → 큰 수탉 죽음 → 동백꽃 화해 |

자동 채점은 필수 개념뿐 아니라 주체·소유·생사를 뒤집는 정규식도 센다. 최종
판정은 자동 점수와 별개로 답변 원문을 사람이 다시 읽었다.

## 2. 기존 파생 값 전수 점검

| 값 | 기존 상태 | 원문 판정 | 조치/현재 상태 |
|---|---:|---|---|
| 분석 청크 | 7 | 기술 단위로 정상 | 7 유지, Agent에는 해시를 노출하지 않음 |
| 전역 서술 | 1인칭 | 맞음. 화자 이름은 미상 | 이름 미상을 등록 인물과 동일시하지 않는 결정적 답변 추가 |
| 등록 인물 | 점순 1명 | 화자는 이름 미상 1인칭 별도 인물 | `role=화자` 자동 카드로 등록, 편집·1클릭 삭제 가능 |
| 점순 카드 소개 | 적대·강직에 치우친 자동 초안 | 초반/한 국면 과적합, 호감과 결말 누락 | 원문은 보존. 향후 프로파일은 전역 균등 표집 |
| 기존 핵심 장면 | 감자 장면 1개 | “집에 감자가 있는지 확인”은 문자적 오독 | 사용자 결정이라 덮어쓰지 않음. Agent는 원문을 더 높은 근거로 사용 |
| 작품 요약 | 1개 | 수탉 죽음 주체가 문법적으로 뒤집혀 신뢰 불가 | 알려진 잔여 실패. Agent 근거로는 낮은 우선순위 |
| 대사 | 30개 인용 중 귀속 3개 | 인용은 30개이며 화자·점순·주변 인물 발화가 모두 필요 | 30/30 수집·화자 골드 30/30, 미상·누락 0 |
| 회상 구간 | 3개 | 청크마다 현재로 리셋되어 큰 회상 프레임 소실 | 5개 타일. 하나의 현재→회상→현재 프레임으로 연결 |
| 사건 | 17, 동일 사건 중복 존재 | 일부 주체·소유·장소 오류 | 17, 정확 중복 0. 개별 품질은 아래 표와 같이 일부 잔존 |
| 플롯 | 1 | 닭싸움 갈등만 뭉뚱그림 | 2개지만 빈 `본줄기`가 남아 품질 미달 |

사건 수만 유지한 채 중복은 제거됐지만, 4·10처럼 주체/소유/장소가 틀린 파생
사건이 남아 있다. 따라서 Agent는 사건 요약을 검색 색인으로만 쓰고, 중요한
주체·생사 질문은 원문 근거 팩과 검증 턴을 우선한다.

## 3. 발견한 원인

1. 1인칭 화자가 `CharacterCard`에 없어서 유일한 등록 인물 점순을 화자로 오인했다.
2. 1,500자 분석 청크가 하나의 장기 회상을 잘라, 중간 청크가 모두 현재로 돌아갔다.
3. 대사와 `하고 … 말했다`가 빈 줄로 분리된 출판 문단이라 같은 줄 규칙이 발화를 0개로 만들었다.
4. 타임라인 도구가 내부 청크 해시를 줬지만 `read_scene`은 그 해시를 읽을 수 없었다.
5. Agent 캐시 키가 사건 “개수” 위주라 같은 개수로 재분석한 값이 바뀌어도 낡은 결과가 남았다.
6. 모델 요약은 유창하지만 조사·소유 표현과 일시적 빈사/실제 죽음을 자주 뒤집었다.
7. 자동 인물 소개와 추론 사건을 원문과 같은 등급으로 다시 주입해 초기 오독이 증폭됐다.
8. 기존 `Utterance`는 화자가 확정된 대사만 보존해, 30개 인용 중 27개가 수집
   목록 자체에서 사라졌다. 1인칭 화자 카드가 없어 `나/내가` 귀속도 불가능했다.

## 4. 변경

- `KnowledgeSidecar` v8: 전역 서술 문맥, 사건 중복 제거, 장기 회상 타일 의미 반영.
- 명시적 경과일 진입과 현재 복귀가 함께 있을 때만 큰 회상 프레임을 결정적으로 생성.
- 큰따옴표 전수 스캐너(ASCII/곡선/겹낫표, 줄바꿈 포함)와 별도 `DialogueLine`을
  추가해 화자 미상도 보존. 앞/뒤 분리 서술, 응답, `또는`·연속 욕설 같은 연속
  발화 표지로 귀속하고 등록 인물이 소유어로만 나온 문장은 화자로 쓰지 않음.
- 이름 미상 1인칭 서술자를 `role=화자` 카드로 자동 등록. 사용자 삭제 거부 표식,
  대사별 화자 오버라이드, 스토리 바이블 전수 목록·원문 점프를 추가.
- 사건 파서와 스냅샷에서 동일 씬·동일 안정 키 중복 제거.
- Agent 타임라인에 공개 장 참조·오프셋·근거·인용 제공, 내부 해시 제거.
- `get_character` 모델 별칭을 `find_character`로 복구하고, 자동 카드 초안은 사실 근거에서 제외.
- 원문·사건·대사·관계·구간·플롯 전체 지문으로 Agent 도구 캐시 무효화.
- 질문별 결정적 근거 팩: 화자, 명시적 시간 프레임, 귀속 대사, 핵심어 원문 발췌,
  수탉의 소유·일시적 빈사/회복·실제 죽음 판정.
- 확신도 높은 화자/회상/대사와 닫힌 조건의 생사·소유 질문은 모델 0회로 답하고, 동기·관계·전체 플롯은
  모델 초안을 원문과 한 번 더 대조한다. 두 번 깨진 도구 마크업은 답변으로 노출하지 않는다.
- 도구 없는 검증 턴은 384토큰으로 제한하고, 원문에서 소유·생사·고추장 전후가
  모두 확정된 경우에만 최종 문장의 `단도` 오기와 일시 우세/최종 패배 역전을 교정한다.
- Agent에 스토리 바이블 전체, 화자 표시 대사 전수 인덱스, 24,000자 이하 원문
  전체를 기본 제공. `get_dialogues`를 더해 조회 도구는 13개.
- 실제 로컬 문서를 읽고 지식 값·도구 trace·답변·지연을 출력하는
  `--dongbaek-agent-bench`, 대사 30개와 Agent 전수 답변을 모델 없이 채점하는
  `--dongbaek-dialogue-bench`, 결정적 회귀 테스트를 추가.

## 5. 실모델 결과

| 실행 | 개념 점수 | 명시 모순 | Agent 7문항 합계 | 사람 검토 |
|---|---:|---:|---:|---|
| 기준선, 512 tokens | 16/29 (55%) | 자동 0 | 약 390.1s | 화자=점순, 감자 동기, 죽은 닭, 시간 구조 등 다수 실패 |
| 320 tokens 실험 | 16/29 (55%) | 자동 0 | 약 291.1s | 도구 호출·시간 답변 중간 절단. 채택 안 함 |
| 결정적 근거 팩 1차 | 21/29 (72%) | 1 | 약 149.3s | 구조 질문 개선, 대사·관계·전체 플롯 잔여 오류 |
| 생사 게이트 전 엄격 판정 | 27/29 (93%) | 1 | 약 100.0s | 전체 플롯에서 우리 수탉의 회복을 죽음으로 쓴 1건 잔존 |
| 최종 엄격 판정 | **29/29 (100%)** | **0** | 약 **92.1s** | 사람 재검토에서도 주체·소유·생사·순서 역전 없음 |
| 대사 전수·넓은 원문 컨텍스트 | **29/29 (100%)** | **0** | 약 **45.3s** | 30개 대사 화자 전수 일치. 7문항 중 관계 해석만 모델 사용 |

기준선 대비 자동 개념 정확도는 +45%p, 7문항 합산 지연은 약 76% 감소했다.
최종 실행은 품질 게이트 `80% 이상 + 명시 모순 0`을 통과했다. 중간 실행 하나는
전체 플롯 검증이 6분 11초에도 끝나지 않아 중단했으며 정상 표본에서 제외했다.
그 장기 꼬리를 계기로 도구 없는 검증 턴만 384토큰으로 제한했다. 최종 수치는
temperature 0.3 단일 실행이므로 모델 변동성까지 보증하는 반복 통계는 아니다.
마지막 실행은 화자·감자·생사·시간·대표 대사·전체 플롯을 닫힌 원문 조건의
결정적 답변으로 전환해 여섯 문항이 모델 0회였다. 관계 해석 한 문항만 45.3초가
걸렸고, 자동 점수 29/29·명시 모순 0을 다시 통과했다.

재현:

```bash
swift run -c release MINTBench \
  --dongbaek-agent-bench \
  --model mlx-community/Qwen3.6-35B-A3B-4bit \
  --temperature 0.3 --max-tokens 512
```

대사 전수 채점(모델·Metal 불필요):

```bash
swift run MINTBench --dongbaek-dialogue-bench
```

결과: 큰따옴표 30/30, 화자 30/30, 미상 0, 누락 0. Agent는 같은 30개를
화자별로 전부 답했고 모델 호출은 0회였다.

## 6. 남은 우선순위

1. **P0 — 저장 전 생사/소유 파생 사실 게이트**: Agent 답변 경로는 방어했지만,
   기존 작품 요약에는 아직 주체 역전이 남는다. 원문 인용과 모순이면 저장하지 않는다.
2. **P0 — 장면·작품 요약 주체 검증**: 현재 7개 중 2개 치명 오류. 행위자-행동-
   대상-소유 구조와 원문 근거 위치 없이는 상위 요약에 올리지 않는다.
3. **P1 — 사건 위치 스키마**: 씬 해시만이 아니라 사건의 로컬 원문 위치를 저장해
   부분 회상 씬의 사건도 실제 시간순으로 안전하게 재배열한다.
4. **P1 — 플롯 빈 본줄기 억제**: 제목·요약이 빈 폴백 스레드는 UI/Agent에 지식처럼 노출하지 않는다.
5. **P1 — 관계 해석 어휘 품질**: 최종 답은 사실 축을 통과했지만 `피부림`,
   `금기된 친밀성`처럼 원문보다 센 어휘가 한 실행에서 나타났다. 반복 평가와
   근거 없는 심리 어휘 억제가 더 필요하다.

기존 점순 카드와 핵심 장면은 사용자 데이터이므로 자동으로 고치지 않았다. 사용자가
직접 확정하지 않은 자동 초안임을 표시하고 Agent 신뢰도만 낮췄다.
