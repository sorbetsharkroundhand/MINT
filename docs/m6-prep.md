# M6 구현 준비 — "살아있는 바이블" 착수 설계 (2026-07-14)

PLAN §14 M6 체크리스트를 구현 순서·인터페이스·측정 게이트로 구체화한다.
근거 수치: M5 리플레이 벤치([m5-replay-bench.md](m5-replay-bench.md)) —
**지식 주입 없는 창 확대는 수락 프록시를 올리지 못했다.** M6의 존재 이유가
측정으로 확인된 상태에서 출발한다.

## 출발점 — 이미 있는 자산

| 자산 | 위치 | M6에서의 역할 |
|---|---|---|
| `DocumentOutline` | Knowledge/ | 씬 해시(더티 추적 키)·`scenes(upTo:)`(시점 차단) — **소비자가 없던 원형의 첫 소비자가 BackgroundIndexer** |
| `ContextAssembler` | Inference/ | A 헤더·카드 ≤3장 조립 — B 블록(요약)이 여기에 추가된다 |
| `PromptCacheBox` | Inference/ | 서픽스 LCP KV 재사용 (웜 0.02s 입증) — A+B 프리웜의 기반 |
| `CharacterCard` + 바이블 v0 팝오버 | EntryStore·CharacterBibleView | 수동 카드 — 자동 감지·프로파일링이 채울 그릇 |
| `generateFolderName` 패턴 | 엔진 one-shot API | 백그라운드 LLM 호출의 프롬프트·파싱·실패 무시 선례 (PLAN §9) |
| 리플레이 벤치 | MINTBench `--replay` | M6 품질 게이트 측정기 (픽스처·절차 고정됨) |

## 구현 순서 (의존성 순 — 각 단계가 독립 머지 가능)

**1. `KnowledgeStore` — 사이드카 저장 골격** (PLAN §6 저장 형식)
- `~/Documents/MINT/knowledge/<entryID>.json`, 최상단 `schemaVersion` + `generation`.
- v1 스키마는 요약 노드만: `SummaryNode(anchor: 씬 해시, headingPath, summary, updatedAt)`.
  바이블·사건은 다음 단계에서 같은 파일에 섹션 추가 (스키마 버전 올리면 삭제·재구축 — 마이그레이션 없음).
- actor로 격리, EntryStore와 분리 (CLAUDE.md §4 — 지식 로직은 Knowledge/에).
- **완료 판정**: 스키마 버전 불일치 파일을 만나면 버리고 빈 상태로 시작하는 것 확인.

**2. `BackgroundIndexer` — 파이프라인 골격 + 첫 작업(씬 요약)** (PLAN §9)
- 2단 트리거: 빠른 패스(타이핑 유휴 ~5s, 예측 디바운스와 별도 타이머) ·
  깊은 패스(장기 유휴 ~60s·앱 비활성). v1 작업은 **더티 씬 요약 하나만** —
  골격(트리거·선점·게이트·메모)을 최소 작업으로 검증한 뒤 작업을 늘린다.
- 백그라운드 3요건(CLAUDE.md §4) 체크리스트:
  - 선점: 예측 요청 도착 → `Task.cancel()` (엔진 협조 취소는 기존 인프라). 씬 단위 체크포인트.
  - 게이트: `thermalState >= .serious` 또는 저전력이면 깊은 패스 보류.
  - 메모: 작업 키 = (작업 종류, 씬 contentHash, schemaVersion). `DocumentOutline`의 해시를 그대로 쓴다.
- 요약 프롬프트: one-shot instruct "이 장면을 1–2문장(≤120자)으로" — `generateFolderName` 패턴 복제.
- **완료 판정**: 타이핑 중 지연 무회귀(E2E) + 같은 씬 재요약 0회(로그로 확인).

**3. 요약 피라미드 상향 전파 + B 블록 조립** (PLAN §6.1·§11)
- 더티 씬 요약 갱신 → 부모 장 요약(≤300자) → 작품 요약(≤500자), **더티 경로만**.
- `ContextAssembler`에 B 블록: `outline.scenes(upTo: cursor)`의 요약을
  (작품 요약 → 커서 이전 장 요약 → 직전 씬 요약) 순으로, 토큰 예산 내 근→원 순 삭감 (PLAN §10 예산).
- **여기서 1차 품질 게이트**: 리플레이 벤치 ①Fast ②M5 ③B 블록 포함 3구성 재측정.
  프록시 보조 지표(정답 명사 포함률)를 벤치에 병기 (m5 문서의 후속 항목).

**4. 인물 감지 깔때기 + 확인 UX + 프로파일링** (PLAN §7)
- 결정적 후보 추출(조사 제거 빈도 + 대화 인접 가중) → 임계(3+ 씬·5+ 언급) →
  사이드바 배지(비모달) → 승인 시 LLM 프로파일링 1회 → CharacterCard 초안.
- 거부 목록 유지 — 같은 후보 재질문 금지. **자동 등록 절대 금지** (CLAUDE.md §3).

**5. 사건 로그 + StateDelta + 역색인** (PLAN §6.2–6.3) — 깊은 패스 작업 추가.
`state_at(pos)` fold 질의가 카드의 "상태@커서" 줄을 만든다.

**6. 대화 귀속 + 존대 매트릭스 v1** (PLAN §6.4·§7) — 결정적 우선(인접 서술·교대 규칙),
모호할 때만 LLM. 산출은 카드의 말투·관계 줄.

**7. A+B 프리픽스 KV 프리웜** (PLAN §12) — B 블록이 안정된 뒤 마지막에.
프리웜 무효화 빈도를 먼저 측정하고 붙인다 (§16 열린 질문).

**8. 바이블 패널 UI** — 팝오버 → 패널 승격, `locked`·미확인 검토. 4~6과 병행 가능.

## 선결정 사항 (착수 전 확정 필요)

1. **Indexer의 소유자**: `EntryStore` 옆의 앱 수준 싱글턴(엔진처럼) 권장 —
   문서 전환 시에도 큐가 살아야 한다. 편집 이벤트는 EntryStore 저장 디바운스에
   업혀서 받지 말고 별도 유휴 타이머로 (예측 디바운스와 간섭 금지).
2. **요약 언어 품질**: nano(1.5B)의 한국어 요약이 쓸만한지 — 2단계에서 씬 10개
   수동 검수. 미달이면 요약만 air(3B) 검토는 **단일 모델 원칙 위반**이라
   기각하고, 프롬프트·후처리로 해결하거나 §16에 기록.
3. **벤치 픽스처 확장**: 바이블 카드 효과를 측정하려면 픽스처에 "카드 없인 못
   맞히는" 컷(1200자 밖 인물 재등장)이 필요 — 3장 추가 여부를 3단계 게이트 전에 결정.

## M6 완료 기준 (PLAN §14에서 전사)

- 1200자 창 밖의 인물·설정을 쓰는 제안이 벤치에서 입증.
- 존대 일치율 유의미 상승.
- 백그라운드 가동 중 타이핑 지연 무회귀.
- 리플레이 수락 프록시 Fast 대비 유의미 상승 (M5에서 이관 — 동일 픽스처·절차).
